# AIOS: Известные баги и обходные пути

## Текущее состояние: известных дефектов нет (чистая сборка)

Начиная с v2.9.1, все тесты проходят, clippy не выдаёт ни одного
предупреждения, а 18 багов, найденных в ходе баг-фикс-фазы v2.7.0
(BUG-021…BUG-038), исправлены и покрыты регрессионными тестами. Переструктурирование TUI ядра на 7 вкладок, флаг загрузки `--safe-mode` и вкладки GUI AI Studio / Network Settings в v2.8.0, а также сохранение чата / шаблоны `/preset` / стриминг в v2.9.0 и перенос этих возможностей в GUI AI Studio в v2.9.1, исправление контраста кнопок в v2.9.2 и Live USB образ в v2.9.5 не добавили новых известных дефектов. См. раздел «Исторические проблемы» и `docs/CHANGELOG.md` v2.8.0 / v2.9.0 / v2.9.1 / v2.9.2 / v2.9.3 / v2.9.5.

### ИСПРАВЛЕНО: GPU-проба Linux не компилировалась (`hw_probe.rs`)
- **Статус:** ИСПРАВЛЕНО в v2.9.5
- **Симптом:** `cargo build` для `target_os = "linux"` падал с `E0308` в `aios/src/hw_probe.rs`: `String::from_utf8(Command::new("lspci").arg("-v").output())` — `output()` возвращает `Result<Output, io::Error>`, а код ожидал `Vec<u8>` (не хватало `.ok()?.stdout`)
- **Причина:** Linux-ветка GPU-пробы никогда не компилировалась (собирались только Windows/macOS); в двух местах забыто извлечение stdout, которое есть в Windows-ветке
- **Исправление:** добавлен `.ok()?.stdout` в Linux-места `nvidia-smi` и `lspci`, а также в эквивалентное macOS-место `system_profiler`
- **Покрытие:** Linux static-musl release сборка теперь компилируется (см. `live/build.sh`); CI для не-Windows целей пока нет

### ИСПРАВЛЕНО: невидимые поля TextEdit в GUI при светлой системной теме
- **Статус:** ИСПРАВЛЕНО в v2.9.3
- **Симптом:** поля ввода на вкладке Network Settings GUI (и другие `TextEdit`) показывали светлый текст на белом фоне — фактически нечитаемо
- **Причина:** eframe 0.31 инициализирует `Visuals` из системной темы ОС; на Windows в светлом режиме `extreme_bg_color` (фон TextEdit) оставался `#FFFFFF`, потому что `AiosTheme::apply` переопределял только `dark_mode` и часть палитры виджетов
- **Исправление:** `apply` теперь задаёт все поля поверхности `Visuals` явно (см. `docs/CHANGELOG.md` v2.9.3); проверено попиксельно на запущенном GUI (поле `#1E1E2A`, текст `#D4D4DF`)
- **Покрытие:** только ручная пиксельная проверка; автоматического GUI-теста пока нет

### ИЗВЕСТНОЕ ОГРАНИЧЕНИЕ: enforcement подписанных манифестов опционален через env
- **Статус:** ПО ЗАМЫСЛУ
- **Симптом:** `store install` / `store update` отклоняют неподписанные или недоверенные блоки, когда задан `AIOS_TRUSTED_PUBLIC_KEYS` (или `trusted_public_keys` источника), хотя та же установка без него проходит
- **Обходной путь:** задавайте `AIOS_TRUSTED_PUBLIC_KEYS` только на системах, где нужны только проверенные установки; оставьте его пустым (по умолчанию), чтобы разрешить неподписанные блоки, сохранив проверку подписи по встроенному ключу
- **Примечание:** путь `store publish` через мост использует `BlockInstaller::new` (без env-ключей), поэтому публикация неподписанных блоков продолжает работать независимо от окружения

### ИЗВЕСТНОЕ ОГРАНИЧЕНИЕ: `store publish` требует работающий сервис обновлений
- **Статус:** ПО ЗАМЫСЛУ
- **Симптом:** `store publish <file.wasm>` падает с ошибкой соединения, когда на `AIOS_BRIDGE_PORT` (по умолчанию `8080`) не слушает сервер моста
- **Обходной путь:** запустите ядро (`cargo run --bin aios`), чтобы мост обслуживал `POST /api/v1/store/publish`, или укажите `AIOS_BRIDGE_PORT` на работающий сервис обновлений
- **Примечание:** wasm-нагрузка кодируется в base64 и проверяется по вычисленному SHA-256 на сервере перед установкой

### ИЗВЕСТНОЕ ОГРАНИЧЕНИЕ: удалённые источники Store требуют сеть
- **Статус:** ПО ЗАМЫСЛУ
- **Симптом:** `store search` / `store install` / `store update` против GitHub или HTTP-источника падают с ошибкой скачивания, когда нет сети или удалённый сервис недоступен
- **Обходной путь:** для офлайн-установки используйте локальный источник (`store add-source local:<path>`) или запустите встроенный сервис обновлений (`aios-bridge` на `AIOS_BLOCKS_DIR`) и укажите `store add-source http://host:port`
- **Примечание:** бинарники блоков проверяются по SHA-256 из манифеста при установке; подделанный payload отклоняется с ошибкой контрольной суммы

### ИЗВЕСТНОЕ ОГРАНИЧЕНИЕ: вкладка Web в TUI отображает только текст
- **Статус:** ПО ЗАМЫСЛУ
- **Симптом:** терминальная вкладка Web не может рендерить CSS/JS/изображения — страницы показываются как структурированный текст (заголовки `#`, списки `•`/`1.`, таблицы `|`, `hr`, изображения как `[alt]`)
- **Примечание:** это внутреннее ограничение терминала, а не регрессия. Для полноценного браузинга используйте нативный браузер: нажмите `W` в любом TUI или откройте вкладку GUI **Browser** (F7)

### ИЗВЕСТНОЕ ОГРАНИЧЕНИЕ: лог чата AI Console — один JSONL-файл без ротации
- **Статус:** ПО ЗАМЫСЛУ
- **Симптом:** `AIOS_DATA_DIR/chat.jsonl` растёт без ротации; каждое сообщение (user + assistant, полный текст) дописывается при каждом ответе, а вся лента перезаписывается при выходе. TUI AI Console и GUI AI Studio используют один и тот же файл по умолчанию, поэтому при старте побеждает последний писавший
- **Обход:** удалите или заархивируйте `aios_data/chat.jsonl`, когда он станет слишком большим; `/clear` очищает ленту на экране, но не удаляет файл
- **Примечание:** файл читается построчно, поэтому повреждённая последняя строка не ломает запуск

### ИЗВЕСТНОЕ ОГРАНИЧЕНИЕ: шаблоны `/preset` были только в памяти
- **Статус:** СНЯТО в v2.9.1 — шаблоны сохраняются в `AIOS_DATA_DIR/presets.json` и в TUI, и в GUI; кастомные шаблоны переживают перезапуск
- **Симптом (снят):** шаблоны, созданные через `/preset <имя> <текст>`, терялись при выходе до подключения персистентности
- **Примечание:** TUI и GUI используют один и тот же путь по умолчанию `AIOS_DATA_DIR/presets.json`, поэтому при старте побеждает последний писавший

## Исторические проблемы (исправлены)

### BUG-001: Падение speed-тестов в debug-режиме
- **Статус:** ИСПРАВЛЕНО
- **Симптом:** `test_serialize_speed` и `test_deserialize_speed` паникуют из-за превышения порога в debug-сборках
- **Причина:** Debug-сборки в 10–20 раз медленнее release из-за отсутствия оптимизаций. Исходные пороги рассчитаны на производительность release-режима.
- **Исправление:** Добавлены двойные пороги через `cfg!(debug_assertions)`: 50мкс для debug, 1мкс для release
- **Затронутые файлы:** `aios-core/src/ipc_protocol.rs:210,234`, `tests/integration_test.rs:95`

### BUG-002: Windows PATH не наследуется cargo
- **Статус:** ОБХОДНОЙ ПУТЬ ПРИМЕНЁН
- **Симптом:** команда `cargo` не найдена при запуске из opencode CLI
- **Причина:** Особенности распространения переменных среды Windows между процессами
- **Обходной путь:** Перед каждым вызовом cargo необходимо выполнить `$env:Path = [System.Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("Path","User")`
- **Затронуто:** все команды cargo

### BUG-003: Clippy-предупреждение `skip_while_next` в intent engine
- **Статус:** ИСПРАВЛЕНО
- **Симптом:** `skip_while().next()` вызывает предупреждение clippy
- **Исправление:** Заменено на паттерн итератора `position().nth()`
- **Затронутый файл:** `aios-tui/src/intent_engine.rs:128-131`

### BUG-004: Clippy-предупреждение `needless_borrow` в block loader
- **Статус:** ИСПРАВЛЕНО
- **Симптом:** `hex::encode(&actual)` вызывает предупреждение о лишнем заимствовании
- **Исправление:** Заменено на `hex::encode(actual)`
- **Затронутый файл:** `aios-block-mgr/src/loader.rs:17`

### BUG-005: Неиспользуемые импорты в интеграционных тестах

- **Симптом:** 8 предупреждений clippy из-за неиспользуемых импортов и изменяемой переменной
- **Исправление:** Удалены неиспользуемые импорты (`BlockState`, `AIOSException`, `ProcessState`, `HealthCheckFn`, `StateTransferManager`, `Arc`, `Mutex`, `thread`) и ключевое слово `mut`
- **Затронутый файл:** `tests/integration_test.rs:1-17,323`

### BUG-006: Приватная функция `now_ms()`, используемая в разных модулях
- **Статус:** ИСПРАВЛЕНО
- **Симптом:** `E0603: function now_ms is private` в aios-security при попытке вызова `capability::now_ms()` из access_control.rs и sandbox.rs

- **Затронутые файлы:** `aios-security/src/capability.rs:141`, `access_control.rs:74`, `sandbox.rs:61,72`

### BUG-007: Тесты watchdog падали без задержки между проверками
- **Статус:** ИСПРАВЛЕНО
- **Симптом:** `test_missed_heartbeats_trigger_suspend` и связанные тесты паникуют, потому что возраст heartbeat составлял 0мс (свежесозданный) и никогда не превышал интервал в 100мс
- **Исправление:** Добавлен `thread::sleep(Duration::from_millis(120))` между вызовами check_timeout; количество итераций цикла уменьшено с 3 до 2 (так как 3 пропущенные проверки вызывают suspend)
- **Затронутый файл:** `aios-watchdog/src/watchdog.rs:207-259`

### BUG-008: Арифметическая ошибка в тесте лимита памяти sandbox

### BUG-009: Отсутствующие импорты типов в context store
- **Статус:** ИСПРАВЛЕНО
- **Симптом:** `E0425: cannot find type TelemetryStore/WorkflowStore/StabilityStore` в store.rs

### BUG-010: Ранний выход из `schedule_next` мешает корректному поведению aging
- **Статус:** ИСПРАВЛЕНО (v0.4.0)
- **Симптом:** `test_scheduler_aging_starvation_prevention` падает — процесс с низким приоритетом и boost aging не выбирается вместо процесса с высоким приоритетом
- **Причина:** Внутренний цикл `schedule_next()` содержал `break` после нахождения первого готового процесса в каждой очереди приоритетов. Из-за aging более поздний процесс в очереди мог иметь более высокий эффективный приоритет, но `break` не позволял проверить всех кандидатов.
- **Исправление:** `break` убран, теперь проверяются все готовые процессы в очереди. Выбирается кандидат с наибольшим эффективным приоритетом.
- **Затронутый файл:** `aios-process-mgr/src/scheduler.rs:320`

### BUG-011: Нестабильные тесты графа зависимостей из-за недетерминированной топологической сортировки
- **Статус:** ИСПРАВЛЕНО (v0.4.0)
- **Симптом:** `test_unload_order_reversed` и `test_block_dependency_graph_ordering` падают с интермитентными ошибками
- **Причина:** Алгоритм Кана обрабатывает узлы через `VecDeque`, инициированный из `HashMap`, что недетерминировано. Независимые узлы (без зависимостей друг от друга) могут появиться в любом порядке. Тесты предполагали фиксированный порядок.
- **Исправление:** Тесты изменены так, чтобы проверялись только ограничения зависимостей (если X зависит от Y, то Y появляется перед X в порядке загрузки), а не абсолютные позиции независимых узлов.
- **Затронутые файлы:** `aios-block-mgr/src/dependency.rs:225-236`, `tests/integration_test.rs`

## Потенциальные будущие проблемы

### RISK-001: Переполнение packet_id в AtomicU64
- **Описание:** `PACKET_COUNTER` в ipc_protocol.rs — это `AtomicU64`, который переполнится после 2^64 пакетов
- **Влияние:** Практически невозможно (потребуются годы при высокой пропускной способности)
- **Меры:** В настоящее время не обрабатывается; можно добавить логику wrapping_add или сброс

### RISK-002: Не рекурсивный поиск `find_by_name`
- **Описание:** `BlockRegistry::find_by_name` выполняет линейный поиск по всем записям
- **Влияние:** O(n) на каждый поиск; пренебрежимо на текущем масштабе, но может стать проблемой при тысячах блоков
- **Меры:** Можно добавить вторичный индекс HashMap по имени -> id

### RISK-003: Отсутствие выгрузки блока во время активного hot-swap
- **Описание:** `BlockLoader::unload_block` выводит предупреждение, но не запрещает выгрузку активного блока
- **Влияние:** Сообщения IPC в процессе обработки могут быть адресованы удалённому блоку
- **Меры:** В продакшене активные блоки должны замораживаться перед выгрузкой

### RISK-004: Watchdog не интегрирован с потоком оркестратора
- **Статус:** ИСПРАВЛЕНО (v0.3.0)
- **Описание:** Кrate watchdog был реализован, но не подключён к потоку AI Orchestrator в main.rs
- **Исправление:** Поток heartbeat watchdog теперь работает в фоне во время сессии TUI; заголовок dashboard отображает актуальное состояние watchdog
- **Затронутые файлы:** `aios-tui/src/main.rs`, `aios-tui/src/dashboard.rs`

### RISK-005: WebView работает в фоновом потоке — несовместимо с macOS
- **Описание:** `WebBrowser` в `aios-webview` запускает цикл событий winit в фоновом потоке; на macOS winit/wry требуют цикл событий в главном потоке
- **Влияние:** Окно браузера не откроется в сборках для macOS
- **Митигация:** Задокументировано, не реализовано. На macOS запускать webview из главного потока приложения или использовать `build_as_child` внутри окна egui (см. TODO Фаза 34)

### RISK-006: GUI-браузер — окно-компаньон, а не встроенное окно
- **Описание:** Вкладка GUI Browser открывает webview в отдельном окне ОС рядом с дашбордом egui, а не как дочернее окно вкладки
- **Влияние:** Косметический UX-пробел — фокус/навигация окна отличается от встроенного браузера
- **Митигация:** Будущая работа: `build_as_child` на Windows/macOS/X11 для рендера внутри вкладки egui (см. TODO Фаза 34)

### BUG-012: get_pending_entries в журнале восстановления игнорирует завершённые ID
- **Статус:** ИСПРАВЛЕНО (v1.0.0)
- **Симптом:** `test_recovery_log_pending` падает — `get_pending_entries()` возвращает завершённые записи вместо их фильтрации
- **Причина:** Функция пропускала строки-маркеры `COMPLETED:`, но никогда не собирала ID из этих маркеров для исключения соответствующих записей. Все записи со статусом `pending` возвращались независимо от того, были ли они помечены как завершённые.
- **Исправление:** Сначала собираются ID завершённых записей из строк `COMPLETED:`, затем записи фильтруются по исключению тех, чей ID находится в наборе завершённых.
- **Затронутый файл:** `aios-persistence/src/recovery.rs:108-140`

### BUG-013: Ядро (`aios`) запускалось с пустым реестром блоков — без браузера
- **Статус:** ИСПРАВЛЕНО (v2.2.0)
- **Симптом:** На новом компьютере ядро стартовало с нулём зарегистрированных блоков; `aios-browser` был обычной библиотекой (без реализации `StatefulBlock`), поэтому браузер при загрузке отсутствовал и системный браузер не запускался автоматически.
- **Причина:** `aios/src/orchestrator.rs:73` создавал пустой `BlockRegistry`; последовательность загрузки 3 блоков существовала только в `aios-tui`/`aiosd`; `BrowserEngine` никогда не реализовывал `handle_message`.
- **Исправление:** Добавлен `BrowserBlock` (`StatefulBlock`) в `aios-browser/src/block.rs`; ядро теперь регистрирует hal/ipc_bus/scheduler/browser при загрузке, делает boot-обнаружение `AIOS_BLOCKS_DIR`, подключает браузерный обработчик к `MessageRouter`, а клавиша `b` в TUI открывает URL в системном браузере через блок.
- **Затронутые файлы:** `aios-browser/src/block.rs`, `aios/src/orchestrator.rs`, `aios/src/tui/mod.rs`, `aios/src/tui/ui.rs`, `aios/src/tui/app_state.rs`, `aios-tui/src/main.rs`, `aios-daemon/src/main.rs`

### BUG-014: Поиск DuckDuckGo терял первую букву URL результатов
- **Статус:** ИСПРАВЛЕНО (v2.2.0)

### BUG-015: HtmlParser::extract_text включал текст `<head>`/`<title>`
- **Статус:** ИСПРАВЛЕНО (v2.2.0)

- **Причина:** `extract_text` вырезал только `<script>`/`<style>` и теги, оставляя текст `<head>`/`<title>` в тексте страницы

- **Затронутый файл:** `aios-browser/src/html_parser.rs:22-36`

### BUG-016: Chaos-тест быстрой генерации ассертил плейнтекст заред актированного отчёта

### BUG-038: wasm `timeout_ms` никогда не применялся — дедлайн эпохи не достигался
- **Статус:** ИСПРАВЛЕНО (v2.7.0)
- **Симптом:** ни один host-тикер не инкрементировал эпоху движка, поэтому `timeout_ms` не действовал как реальный тайм-аут; только лимит топлива ограничивал выполнение (бесконечный цикл крутился до исчерпания топлива)
- **Причина:** `set_epoch_deadline(1)` активировал store, но никто не вызывал `Engine::increment_epoch()`, поэтому дедлайн был недостижим (эпоха движка оставалась 0)

### BUG-039: падение GUI/TUI при определении железа — индекс CSV `wmic` за границей
- **Статус:** ИСПРАВЛЕНО (v2.9.1)
- **Симптом:** `aios-gui` (и любой бинарник, вызывающий `HardwareProfile::detect`) падал при старте с `index out of bounds: the len is 2 but the index is 2` в `aios-hal/src/hardware.rs` — окно GUI не открывалось

- **Тесты:** `test_parse_wmic_memory_csv_full_rows` (две DIMM суммируются, скорость читается) и `test_parse_wmic_memory_csv_short_rows_no_panic` (короткая строка из 2 полей пропускается, валидная всё ещё разбирается)
- **Затронутые файлы:** `aios-hal/src/hardware.rs`
