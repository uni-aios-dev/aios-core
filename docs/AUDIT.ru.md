## 4. Находки и принятые меры

### F1. Нестабильный тайминговый порог в RT-стресс-тесте — ИСПРАВЛЕНО
- **Где:** `tests/stress_test.rs::test_stress_rt_scheduler_500` (строка ~113).
- **Симптом:** падение на этой машине под параллельной тестовой нагрузкой: "RT scheduling took 2.0974127s (>2s)". Сама логика корректна (500 процессов запланировано).
- **Причина:** жёсткий лимит 2 с для измерения реального времени в debug-сборке на загруженной машине — нарушение правила проекта о **двойных порогах debug/release** для скоростных тестов.
- **Исправление:** теперь лимит `5000 мс` при `cfg!(debug_assertions)` и `2000 мс` в release. Повторный прогон теста: зелёный (11/11).
- Файлы: `tests/stress_test.rs`, `docs/BUGS*.md`.

### F2. Несогласованность дорожной карты — ИСПРАВЛЕНО
- `docs/TODO.md` показывал **Phase 46 (aios-autohal)** как незакрытую `[ ]`, хотя все подпункты были выполнены и выпущены в v2.22.0–v2.25.0. Отмечено `[x]` (EN+RU).

### F3. Покрытие документацией
- На уровне вызовов схемы не было; добавлены `docs/SCHEME.md` + `docs/SCHEME.ru.md` (карта функций по крейтам, поток загрузки, поток IPC, вехи микроядра, карта интеграционных тестов).

## 6. Наблюдения и риски (действия сейчас не требуются)

1. **Чувствительность к таймингам**: даже с ослабленными debug-порогами wall-clock-проверки стресс-тестов могут «мигать» на сильно загруженных CI-машинах. При повторении — рассмотреть привязку к CPU или бюджет по перцентилям.
2. **`aios-bridge` без unit-тестов** — поведение покрыто `tests/bridge_tests.rs` (24) и смоук-путями эндпоинтов, но чистой логике (`IntentParser`, round-trip DTO) пригодились бы inline-тесты.
3. **`aios-daemon` без unit-тестов** — приемлемо для бинарника на 183 строки; жизненный цикл косвенно проверяется Docker-эксплуатацией.
4. **Bare-metal-ветка** (`aios-kernel`) по природе без автотестов; верификация — QEMU-вывод, задокументированный в CHANGELOG (v2.26–v2.28). Вехам M3/M4 стоит добавить serial self-check'и.
5. **Отложенная работа**: встраивание webview через `build_as_child`, формальная верификация safety-свойств (TODO → Deferred).
6. **Синхронизация доков**: все шесть двуязычных пар присутствуют и согласованы на момент аудита (ARCHITECTURE, CHANGELOG, BUGS, TODO, INTERFACE + новые SCHEME/AUDIT).

## 7. Заключение

Кодовая база здорова: собирается чисто, clippy без замечаний, форматирование полное, 1338 тестов проходят без сбоев после одного исправления нестабильного порога. Архитектурные правила соблюдаются во всех картированных крейтах. Рекомендуемый следующий шаг разработки прежний — дорожная карта микроядра: **веха 3 — вытесняющая многозадачность** (планировщик по таймеру + переключение контекста + ring 0/3), далее M4 (IPC ядра).
