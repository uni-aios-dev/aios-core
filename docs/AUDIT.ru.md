## 4. Находки и принятые меры

### F1. Нестабильный тайминговый порог в RT-стресс-тесте — ИСПРАВЛЕНО
- **Где:** `tests/stress_test.rs::test_stress_rt_scheduler_500` (строка ~113).
- **Симптом:** падение на этой машине под параллельной тестовой нагрузкой: "RT scheduling took 2.0974127s (>2s)". Сама логика корректна (500 процессов запланировано).
- **Причина:** жёсткий лимит 2 с для измерения реального времени в debug-сборке на загруженной машине — нарушение правила проекта о **двойных порогах debug/release** для скоростных тестов.
- **Исправление:** теперь лимит `5000 мс` при `cfg!(debug_assertions)` и `2000 мс` в release. Повторный прогон теста: зелёный (11/11).
- Файлы: `tests/stress_test.rs`, `docs/BUGS*.md`.

### F2. Несогласованность дорожной карты — ИСПРАВЛЕНО
- `docs/TODO.md` показывал **Phase 46 (aios-autohal)** как незакрытую `[ ]`, хотя все подпункты были выполнены и выпущены в v2.22.0–v2.25.0. Отмечено `[x]` (EN+RU).

### F3. Покрытие документацией
- На уровне вызовов схемы не было; добавлены `docs/SCHEME.md` + `docs/SCHEME.ru.md` (карта функций по крейтам, поток загрузки, поток IPC, вехи микроядра, карта интеграционных тестов).

## 6. Наблюдения и риски (действия сейчас не требуются)

1. **Чувствительность к таймингам**: даже с ослабленными debug-порогами wall-clock-проверки стресс-тестов могут «мигать» на сильно загруженных CI-машинах. При повторении — рассмотреть привязку к CPU или бюджет по перцентилям.
2. **`aios-bridge` без unit-тестов** — поведение покрыто `tests/bridge_tests.rs` (24) и смоук-путями эндпоинтов, но чистой логике (`IntentParser`, round-trip DTO) пригодились бы inline-тесты.
3. **`aios-daemon` без unit-тестов** — приемлемо для бинарника на 183 строки; жизненный цикл косвенно проверяется Docker-эксплуатацией.
4. **Bare-metal-ветка** (`aios-kernel`) по-прежнему без автоматических аппаратных тестов; верификация — QEMU-вывод в CHANGELOG. Вехи M3/M4 выпущены, serial self-check'и существуют, а `aios-kernel-run` теперь содержит 2 unit-теста разбора версии и двойного меню Limine (§8).
5. **Отложенная работа**: встраивание webview через `build_as_child`, формальная верификация safety-свойств (TODO → Deferred).
6. **Синхронизация доков**: все шесть двуязычных пар присутствуют и согласованы на момент аудита (ARCHITECTURE, CHANGELOG, BUGS, TODO, INTERFACE + новые SCHEME/AUDIT).

## 7. Заключение

Базовый аудит завершился чистой сборкой, clippy без замечаний, полным форматированием и 1338 тестами без сбоев после одного исправления нестабильного порога. Актуальный срез v2.84.0 тоже чист: 1824 теста в 100 наборах, ноль сбоев. Архитектурные правила соблюдаются во всех картированных крейтах. Вехи M3/M4 выпущены; оставшаяся работа по §8 — надёжность provisioning (пересборка гибридного образа и прошивка) и аппаратная проверка загрузки с двумя ядрами.

## 8. Исправления после аудита (v2.84.0, 26.11.2026)

Следующие исправления реализованы в коде после базового аудита. Они приведены здесь для прослеживаемости; актуальная карта функций — `docs/SCHEME.ru.md`.

### P1. Честность версии

- `aios-kernel/src/version.rs` — единственный источник отображаемой версии: `SEMVER = env!("CARGO_PKG_VERSION")` и `KERNEL = concat!("AIOS kernel v", env!("CARGO_PKG_VERSION"))`.
- Баннер загрузки и строка конфигурации (`main.rs`), отчёты паники/fatal (`main.rs`, `interrupts.rs`), статус/About/`ver` в TUI (`tui.rs`), а также About/заголовки окон/превью Files в GUI (`gui.rs`) читают эти константы.
- `aios-kernel/Cargo.toml` (`version = "2.84.0"`) — единственный литерал версии; в `aios-kernel/src` не осталось устаревших жёстко заданных строк вида `v2.x.y`, кроме намеренных идентификаторов загрузчика/резервного образа.

### P2. Честность конфигурации

- `aios-kernel/src/config.rs` добавляет `KeyPolicy { Effective, Informational }`, `policy(key)`, `validate_informational()` и `Summary.invalid_values`. `Effective` — только `blocks.<name>.rights` и `blocks.<name>.fuel`; `system.*`, `boot.*`, `net.*` и неизвестные ключи — `Informational`: разбираются, проверяются и логируются с источником, но не применяются как рантайм-настройки.
- Проверяются булевы `boot.debug` / `net.dhcp` и положительное целое `net.mtu`; некорректные информационные значения учитываются и вызывают предупреждение.
- `main.rs` логирует каждую пару `key = "value" (layer, policy)` и сводку `[cfg] system = ... (N layer(s), N key(s), N invalid layer(s), N invalid value(s))`. Таймер `interrupts::TIMER_HZ`, куча `heap::HEAP_SIZE` и версия релиза — факты времени компиляции, а не конфигурационные ключи.
- Стандартные шаблоны `boot/assets/aios/config/{system,net,blocks}.conf` содержат соответствующие комментарии Effective/Informational; их копии в `boot/out/assets/aios/config` побайтово идентичны (проверено SHA-256).

### P3. Проверка указателей ring 3

- `aios-kernel/src/memory.rs` определяет `USER_SPACE_LIMIT` (`0x0000_8000_0000_0000`), `user_range(virt,len)`, `translate_user(virt,len,write)` и `walk_user_leaf()`. `translate_user` — **единственные** врата для пользовательских буферов `int 0x80`: отклоняет null (кроме `len == 0`), адреса верхней половины / неканонические адреса, переполнение `virt + len`, неотображенные страницы, PTE только для супервизора и страницы только для чтения при записи. Флаги `PRESENT|USER` проверяются на уровнях PML4/PDPT/PD/leaf, `WRITABLE` — на каждом уровне при записи, включая huge pages.
- `syscalls.rs` использует `user_read` / `user_write`, возвращающие `Option`, `write_user_string` с циклом без переполнения, `u64::MAX` для некорректных буферов сокетов и однократную проверку всего диапазона. `gui.rs` `SYS_GUI CREATE` проверяет 16-байтовый `CreateReq`, область буфера и заголовок через `translate_user`; `draw_client()` повторно проверяет буфер клиента при каждой компоновке кадра. `memory::translate()` остаётся только для ядра/драйверов/DMA.

### P4. Надёжность прошивки

- `scripts/flash-usb.ps1` блокирует и размонтирует тома через `DeviceIoControl` (`FSCTL_LOCK_VOLUME` / `FSCTL_DISMOUNT_VOLUME`), открывает физические диски с `FileMode.Open` + `FileShare.ReadWrite`, пишет выровненные по 512-байтовым секторам дополненные блоки по 1 МиБ, вызывает `Flush($true)` и затем снимает блокировки.
- Восстановление выполняет ограниченные по времени задания `Update-Disk` + `pnputil /rescan-disks` с `AIOS_FLASH_RECOVERY_TIMEOUT` (по умолчанию 30 с) и опрашивает готовность диска вместо зависания на `ERROR_NOT_READY`.
- Полная контрольная сумма SHA-256 прочитанного образа должна совпасть с исходной; дополнительно проверяется сигнатура MBR `55 AA`. При повторном запуске от имени администратора весь вывод пишется в один временный лог, который родительский процесс выводит один раз.

### P5. Гибридная сборка

- `aios-kernel-run/src/main.rs` читает версию ядра из секции `[package]` файла `aios-kernel/Cargo.toml`, формирует метку текущей записи как `v<major>.<minor>+` (`v2.84+`), размещает оба ELF (текущий и резервный) и записывает меню Limine с двумя записями (текущая + откат `v2.79`). Устаревший ISO удаляется перед пересборкой.
- `verify_hybrid_image()` проверяет MBR `55 AA` и маркеры ISO9660 `CD001` и на ISO, и на USB IMG. Резервный ELF по умолчанию — `aios-kernel-run/out/aios-kernel-v279.elf`, если он есть; в чистых клонах нужно передать реальный ELF через `AIOS_FALLBACK_KERNEL`, а `AIOS_FALLBACK_VERSION` по умолчанию равен `v2.79`.
- **Здесь не выполнялось:** свежая пересборка гибридного образа не проводилась — в этой среде отсутствуют `xorriso.exe` (`iso/msys/usr/bin`) и бинарники Limine (`iso/limine/limine-binary`). Удалось проверить только код и unit-тесты (`aios-kernel-run` — 2/2). Существующая физическая флешка остаётся **только Legacy-BIOS**, пока не будет прошита чисто пересобранным гибридным образом.

## 9. Повторная проверка безопасности (27.11.2026)

- Аутентификация моста усилена помимо исходного аудита: PBKDF2-HMAC-SHA256 с constant-time проверками, регистрация по включению, CORS по fail-closed, токен WS при каждом повышении и ограниченные DTO. Регистрация и логин теперь делят проверку длины учётных данных до хеширования, а учёт неудачных входов очищается и ограничен 10 000 записей.
- SSRF-политика браузера теперь проверяет каждый hop, привязывает DNS-ответы к проверенным адресам через `resolve_to_addrs`, читает тела под лимитом байт и явно сообщает об ошибке сборки клиента.
- Проверены прямые `reqwest`-клиенты (`aios-llm`, `aios-search`, `aios-store`, `aios-autohal`): их URL приходят из конфигурации/окружения оператора или фиксированных значений, а запросы моста не могут передать `api_url`/store URL. Удалённо управляемой SSRF-цели не найдено.
- Верификация: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (1 858 пройдено / 0 провалено в 100 наборах) и `scripts/check_unsafe_safety.py HEAD~1` зелёные.
- Оставшаяся открытая проблема — задокументированный page fault в ring 0 `code=0x20000000` (см. `docs/BUGS.ru.md`); новых находок по безопасности хостовой части в этом проходе нет.
