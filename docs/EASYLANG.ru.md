# EasyLang Core — справочник по языку и компилятору

Версия v2.73.0 (`boot/aios-easylang`, веха M3.3).

EasyLang Core — исходный язык WebAssembly-блоков AIOS. Это небольшой
императивный язык над `i32` ровно с четырьмя host-вызовами; `aios-easylang`
компилирует его в подмножество, которое проверяет и исполняет `aios-wasmhost`.
Внешний тулчейн не нужен: компилятор собран как `#[no_std]` + `alloc`, поэтому
тот же код позже сможет компилировать блок прямо внутри ядра.

## Конвейер

```text
boot/assets/aios/easylang/*.easy
        │  aios-easylang::compile
        ▼
aios/blocks/<stem>.wasm          (одна страница строк, один экспорт `run`)
        │  aios-image → FAT32 ESP
        ▼
шаг 6 загрузки ядра: aios-wasmhost (parse → проверка прав → запуск)
```

* Один файл `*.easy` даёт один блок. Имя файла без расширения становится именем
  блока: `hello.easy` → `blocks/hello.wasm` → ключ политики `blocks.hello.*`.
* Сгенерированные `.wasm` — результат сборки, а не исходники: единственный
  закоммиченный исходник штатного блока — `boot/assets/aios/easylang/hello.easy`.

## Быстрый старт

```powershell
# скомпилировать файл рядом с исходником (hello.easy -> hello.wasm)
cargo run --manifest-path boot/aios-easylang/Cargo.toml --release -- hello.easy

# скомпилировать в каталог блоков с явным именем
cargo run --manifest-path boot/aios-easylang/Cargo.toml --release -- `
    boot/assets/aios/easylang/hello.easy -o boot/out/hello.wasm

# только проверить синтаксис и типы, ничего не записывая
cargo run --manifest-path boot/aios-easylang/Cargo.toml --release -- hello.easy --check
```

Штатный образ компилирует все `.easy` автоматически:

```powershell
cargo run --manifest-path boot/aios-image/Cargo.toml --release -- --headless --timeout 20
```

Ожидаемое доказательство в serial-логе:

```text
aios-image: compiled hello.easy -> blocks/hello.wasm (95 bytes)
[serial] [block] blocks/hello.wasm: hello from aios-wasmhost
[serial] [block] blocks/hello.wasm ran: entry 'run' (1 page(s))
[serial] [block] blocks/hello.wasm used 5 of 20000 instruction(s)
```

## Модель программы

* Весь файл — это тело экспортируемой функции `run`.
* У `run` нет параметров и нет возвращаемого значения. Запускающий код ядра
  вызывает `run` (или `_start` для рукописных модулей) с пустым списком
  аргументов.
* Пользовательских функций, рекурсии, модулей и параметров нет.
* Инструкции выполняются сверху вниз. `exit` завершает блок; достижение конца
  файла — обычный возврат.

## Лексика

| Элемент | Правило |
| --- | --- |
| Кодировка | ASCII вне строковых литералов; не-ASCII байт вне строки — ошибка. В строковых литералах допустим любой корректный UTF-8. |
| Комментарии | `#` до конца строки. |
| Разделители | Инструкцию завершает перевод строки или `;`. Перевод строки внутри `{}` тоже разделяет инструкции. |
| Идентификаторы | `[A-Za-z_][A-Za-z0-9_]*`. |
| Ключевые слова | `let`, `if`, `else`, `while`, `log`, `exit`, `yield`, `and`, `or`, `not`, `true`, `false` — зарезервированы всегда. |
| Целые числа | Только десятичные цифры, без знака, без `_`, без `0x`, не больше `2147483647` (`i32::MAX`). Отрицательное значение — это префиксный оператор `-`. |
| Строки | Двойные кавычки, одна строка. Экранирование: `\n`, `\t`, `\r`, `\\`, `\"`, `\0`. Другие escape-последовательности и «сырой» перевод строки — ошибка. |
| Позиции | Номер строки с 1, номер байтового столбца с 1. |

Ключевые слова и идентификаторы регистрозависимы. `True` — идентификатор, а не
логическое значение.

## Типы

В EasyLang один тип: знаковый 32-битный `i32`.

* `true` — это `1`, `false` — `0`.
* Условие ложно, когда оно равно `0`, и истинно во всех остальных случаях.
* Сравнения (`==`, `!=`, `<`, `<=`, `>`, `>=`) и `and`, `or`, `not` дают ровно
  `0` или `1`.
* `+`, `-`, `*` переполняются с заворотом (семантика WebAssembly).
* `/` и `%` — знаковые; деление или остаток на ноль дают ловушку
  `DivideByZero`, а `i32::MIN / -1` — `IntegerOverflow`.
* `and` и `or` **не замыкаются**: вычисляются оба операнда, затем каждый
  нормализуется в `0`/`1`, и только потом выполняется операция.
* Унарный `-x` генерируется как `0 - x`; `not x` — как `x == 0`.

## Инструкции

| Синтаксис | Смысл |
| --- | --- |
| `let name = expr` | Объявить переменную и инициализировать её. |
| `name = expr` | Присвоить переменной, объявленной раньше в исходнике. |
| `log "text"` | Записать одну UTF-8 строку в host-лог. Аргумент обязан быть строковым литералом. |
| `exit expr` | Остановить блок со статусом `i32`. Ядро считает это нормальной остановкой. |
| `yield` | Вызвать host-хук уступки. |
| `if cond { ... } else { ... }` | Ветвление. Фигурные скобки обязательны; `else` необязателен. |
| `while cond { ... }` | Цикл с проверкой перед телом. Фигурные скобки обязательны. |

Примеры:

```text
# инструкции разделены переводом строки
let sum = 0
let i = 5
while i > 0 {
    sum = sum + i
    i = i - 1
}
exit sum
```

```text
# та же программа с разделителями ';'
let x = 2; if x < 3 { log "small" } else { log "large" }
```

`else` может начинаться на строке после закрывающей `}` ветви `then`.
Всё остальное должно быть на одной строке либо продолжаться после `{`/`}`/`;`.

## Выражения

Приоритеты от самого слабого к самому сильному:

| Уровень | Операторы | Ассоциативность |
| --- | --- | --- |
| 1 | `or` | левая |
| 2 | `and` | левая |
| 3 | `==` `!=` `<` `<=` `>` `>=` | левая |
| 4 | `+` `-` | левая |
| 5 | `*` `/` `%` | левая |
| 6 | префиксные `-` `not` | правая |
| 7 | литерал, переменная, `now_ms()`, `true`, `false`, `( expr )` | — |

Сравнения левоассоциативны, поэтому `a < b < c` разбирается как
`(a < b) < c`; пишите `a < b and b < c`.

`2 + 3 * 4 - 10 / 5 % 3` даёт `12`.

## Переменные

* Переменные имеют область видимости на всю функцию. Блочных областей нет.
* В программе может быть не больше **16** переменных (`MAX_LOCALS`).
* Имя объявляется один раз; второй `let` — ошибка.
* Переменная должна быть объявлена до использования **в порядке исходника**.
  Анализ идёт одним проходом, поэтому `let` внутри ветви `if` виден в более
  поздней ветви `else` и после `if`, хотя выполняется не на всех путях.
* Локальные переменные WebAssembly стартуют с `0`. Чтение переменной, чей `let`
  не выполнился на данном пути, поэтому даёт `0`.
* `now_ms` особый в позиции выражения: `now_ms` без `()` — синтаксическая
  ошибка, поэтому не используйте это имя для переменной.

```text
let total = 0
if now_ms() % 2 == 0 {
    let parity = 1
} else {
    parity = 0          # виден: `let` встретился раньше в исходнике
}
total = total + parity  # 0 на ветви, где `let` не выполнялся
```

## Строки и память

* `log` принимает только строковый литерал. Конкатенации, форматирования,
  интерполяции и строковых переменных нет.
* Все литералы склеиваются в порядке исходника в один blob, который лежит по
  смещению `0` одного data-сегмента в одной странице линейной памяти.
  Одинаковые строки не дедуплицируются.
* Blob обязан поместиться в одну страницу: **65 536 байт суммарно** на
  программу, иначе компиляция завершается ошибкой.
* Программа без `log` вообще не объявляет память.
* Байты строк копируются как есть, поэтому UTF-8 и `\0` сохраняются. Хост
  проверяет UTF-8 при логировании; некорректные байты выводятся как
  `<block log is not UTF-8>`.

## Host ABI

Каждая конструкция отображается ровно в один импорт. В модуль попадают только
использованные импорты, всегда в таком порядке:

| Конструкция | Импорт | Сигнатура | Нужное право | Действие в рантайме |
| --- | --- | --- | --- | --- |
| `log "text"` | `aios.log` | `(i32 ptr, i32 len) -> ()` | `log` | `Env::log(text)`; стоит `1 + len/64` топлива |
| `exit code` | `aios.exit` | `(i32 code) -> ()` | `exit` | `Trap::Exited(code)`; нормальная остановка для ядра |
| `now_ms()` | `aios.now_ms` | `() -> i32` | `clock` | `Env::now_ms()` в миллисекундах |
| `yield` | `aios.yield` | `() -> ()` | `yield` | `Env::idle()` |

Программе без host-вызовов права не нужны (`Rights::NONE`). Блок, чьи
`required_rights()` не покрыты токеном, пропускается до исполнения.

В ядре `Env` реализует `SerialEnv`: `aios.log` превращается в
`[serial] [block] <name>: <text>`, `aios.now_ms` читает счётчик тиков PIT,
а `aios.yield` пока вызывает стандартный пустой хук `idle`.

## Сгенерированный модуль

Для программы хотя бы с одним `log` компилятор пишет:

| Секция | Содержимое |
| --- | --- |
| Type | сигнатура `run` `() -> ()` плюс по одной сигнатуре на каждый использованный импорт |
| Import | только использованные функции `aios.*` в порядке `log`, `exit`, `now_ms`, `yield` |
| Function | ровно одна функция — `run` |
| Memory | одна страница, без максимума |
| Export | `run` по индексу функции после импортов |
| Code | тело `run`, не более 16 дополнительных локальных `i32` |
| Data | один активный сегмент по смещению `0` со строковым blob |

Без единого `log` нет ни памяти, ни data-секции. Модуль никогда не использует
таблицы, глобалы, секцию элементов, data-count и start-функцию.

## Интерфейс командной строки

```text
aios-easylang <input.easy> [-o <output.wasm>] [--check]
aios-easylang -h | --help
```

| Флаг | Поведение |
| --- | --- |
| `-o`, `--output` | Путь результата. По умолчанию — входной путь с расширением `.wasm`. |
| `--check` | Скомпилировать и напечатать `<input>: ok (N bytes)`, ничего не записывая. |
| `-h`, `--help` | Напечатать использование и успешно завершиться. |

* Принимается ровно один входной файл.
* Вход обязан быть корректным UTF-8 (`fs::read_to_string`).
* Код возврата `0` при успехе и `1` при любой ошибке.
* Ошибки идут в stderr в виде `<path>: <line>:<column>: <message>`.

## Интеграция с образом

`aios-image` запускается без аргументов из корня репозитория и делает так:

1. собирает `aios-boot` и ядро;
2. копирует `boot/assets` в `boot/out/assets`;
3. компилирует каждый `aios/easylang/*.easy` (с сортировкой по имени файла) в
   `aios/blocks/<stem>.wasm`;
4. удаляет `aios/easylang` из стейджинга, поэтому на ESP попадает
   скомпилированный блок, а не исходник;
5. пишет GPT-диск с FAT32 ESP и проверяет `/aios/blocks/hello.wasm` среди
   обязательных путей.

Каталог `boot/out` генерируется и находится в `.gitignore`. Чтобы добавить
блок, закоммитьте `boot/assets/aios/easylang/<name>.easy` и политику для него
либо положитесь на значение «без прав» по умолчанию и предупреждение в логе
ядра.

## Политика блоков

Политика лежит в найденном drop-in-файле, например
`boot/assets/aios/config/blocks.conf`:

```ini
# список через запятую из log, exit, clock, yield
blocks.hello.rights = log
# бюджет инструкций; отсутствие означает DEFAULT_FUEL (100000)
blocks.hello.fuel = 20000
```

Оба ключа имеют статус `Effective` в `config::KeyPolicy`: WASM-хост использует
`blocks.<stem>.rights` и `blocks.<stem>.fuel` при загрузке. Остальные поставляемые
ключи конфигурации (`system.*`, `boot.*`, `net.*`) информационные — они только
разбираются, проверяются и логируются.

* Отсутствие `blocks.<stem>.rights` даёт `Rights::NONE` и предупреждение в логе
  ядра; блок, которому нужен любой host-доступ, после этого пропускается.
* Неизвестное имя права приводит к пропуску блока.
* `blocks.<stem>.fuel` обязан помещаться в `u32`; отсутствующее или
  некорректное значение заменяется на `DEFAULT_FUEL`.
* Блоки выполняются один раз при загрузке, до планировщика, поэтому топливо —
  единственный лимит времени. Ловушка или исчерпанный бюджет помечают блок как
  failed, но никогда не останавливают ядро.

## Диагностика

Каждая ошибка несёт позицию и сообщение в нижнем регистре без точки в конце:

```text
hello.easy: 3:5: unknown variable 'nope'
hello.easy: 1:1: variable 'x' is declared twice
hello.easy: 4:9: log expects a string literal, found 'x'
hello.easy: 2:1: expected a new line or ';' after the statement
```

Частые ошибки:

| Сообщение | Причина |
| --- | --- |
| `integer literal is too large` | Значение больше `2147483647` или отрицательный литерал без унарного `-`. |
| `a number cannot be followed by a letter` | `1x` вместо `1` и отдельного идентификатора. |
| `unterminated string` / `unknown escape '\x'` | Плохой литерал; поддерживаются только `\n \t \r \\ \" \0`. |
| `expected a new line or ';' after the statement` | Две инструкции на одной строке без `;`. |
| `log expects a string literal` | `log x` или `log 1`. |
| `variable 'x' is declared twice` | Повторный `let`; затенение запрещено. |
| `unknown variable 'x'` | Использование до `let` или опечатка. |
| `cannot assign to unknown variable 'x'` | Присваивание без предшествующего `let`. |
| `too many variables (at most 16)` | Больше 16 имён. |
| `the logged text does not fit in one memory page (65536 bytes)` | Слишком большой строковый blob. |
| `blocks are nested too deeply (at most 64)` | Больше 64 кадров управления; каждый `if` — один, каждый `while` — два. |
| `expected '{'` / `expected '}'` | Нет фигурных скобок вокруг тела ветви или цикла. |
| `expected an expression` | Пустая правая часть, например `exit`. |

Столбец считается в байтах строки. Для ASCII-синтаксиса это точная позиция; для
многобайтового символа внутри строки он указывает на первый байт.

## Лимиты

| Пункт | Лимит | Где проверяется |
| --- | --- | --- |
| Число переменных | 16 | `aios-easylang` (`MAX_LOCALS`) |
| Вложенность кадров управления | 64 (`if` = 1, `while` = 2) | `aios-easylang` / `aios-wasmhost` |
| Строковый blob | 65 536 байт | `aios-easylang` |
| Линейная память | 1 страница (хост разрешает 16) | `aios-easylang` |
| Целочисленный литерал | `i32::MAX` | лексер |
| Вызовы функций / глубина вызовов | нет (нет пользовательских функций) | язык |
| Итерации цикла | ограничены только топливом | рантайм |
| Топливо | `blocks.<stem>.fuel`, по умолчанию `100000` | ядро |
| Исполнение | один раз при загрузке, в один поток | запуск блоков в ядре |

## Примеры

### Hello

```text
# boot/assets/aios/easylang/hello.easy
log "hello from aios-wasmhost"
```

Нужно `blocks.hello.rights = log`.

### Сумма и статус

```text
let sum = 0
let i = 5
while i > 0 {
    sum = sum + i
    i = i - 1
}
exit sum          # Trap::Exited(15), нормальная остановка
```

Нужно право `exit`; памяти сверх кода не требуется.

### Часы и кооперативная уступка

```text
let start = now_ms()
let spins = 0
while now_ms() - start < 100 {
    spins = spins + 1
    yield
}
log "waited 100 ms"
exit spins
```

Нужны права `clock`, `yield`, `log` и `exit`.

## Вне задач

В EasyLang Core намеренно нет пользовательских функций, массивов, строковых
значений, чисел с плавающей точкой, короткого замыкания, импортов сверх четырёх
host-вызовов и способа объявить capability прямо в языке. Блоки остаются только
загрузочными, пока планировщик не научится держать их как процессы (M4); тогда
же тот же компилятор сможет работать в ядре, а те же ключи политики — применяться
к процессам.

отказ в правах, учёт топлива и позиции в исходнике.
