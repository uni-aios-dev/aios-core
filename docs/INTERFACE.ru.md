# Интерфейс AIOS — Руководство пользователя

## Live USB (загрузочная флешка)

Загрузочная флешка AIOS (`AIOS-LIVE`, гибридный BIOS+UEFI ISO) загружается сразу в TUI ядра AIOS на `tty1`. Промпта входа нет.

- Загрузите машину с флешки (меню загрузки BIOS/UEFI → USB). GRUB показывает меню (10 с по умолчанию):
  1. **AIOS Live** — тихая загрузка, автозапуск TUI AIOS
  2. **AIOS Live (verbose console)** — то же, но видны сообщения ядра
  3. **AIOS Installer (install to disk)** — та же тихая загрузка; далее запустите `aios-install`
- В TUI нажмите `Esc`/`q`, чтобы выйти в шелл `#`. Система только для чтения (squashfs); записываемы только `/tmp`, `/run`, `/var/log` (tmpfs). Изменения не сохраняются между перезагрузками.
- Сеть: при загрузке выполняется попытка DHCP на всех ethernet/wifi-интерфейсах (см. вкладку Network в TUI — там адрес).
- Чтобы установить AIOS на диск машины, введите `aios-install`. Установщик покажет список дисков, запросит целевой (например `sda`), потребует подтверждения `YES`, разметит диск (GPT: 512 МБ EFI + ext4 root), скопирует систему и установит GRUB. Перезагрузитесь после сообщения об успехе.

## Обзор

AIOS предоставляет два интерфейса для управления системой:

| Интерфейс | Тип | Бинарник | Назначение |
|-----------|-----|----------|------------|
| **Web** | Браузерный SPA (HTML/CSS/JS) | `aios-studio/` на `http://<host>:<port>/` | Удалённое управление, визуальный дашборд, любое устройство |
| **TUI** | Терминальный (ratatui) | `aios-tui` | SSH, интерактивный, клавиатура |
| **GUI** | Нативное окно (egui/eframe) | `aios-gui` | Desktop, визуальный дашборд, мышь + клавиатура |
| **Daemon** | Фоновый сервер | `aiosd` | Docker, фон, CI/CD, без терминала |

Оба интерфейса отображают одни и те же данные и предоставляют одни и те же операции. GUI — это графический аналог TUI.

### Вкладки

- **Обзор**: Информация о системе (CPU, GPU, хранилище) + журнал активности
- **Процессы**: Таблица с PID, Имя, Приоритет, Состояние, RAM, CPU, Сбои + панель деталей
- **Блоки**: Таблица с ID, Имя, Версия, Состояние, Размер + операции загрузки/выгрузки/замены
- **Метрики**: Шкала RAM, распределение приоритетов, график истории RAM
- **Зависимости**: Граф зависимостей + цепочка загрузки
- **Web**: Омнибокс (запрос или URL), текст страницы (заголовки подсвечены), список ссылок — страницы грузятся в фоне, а до 20 недавних страниц кэшируются, поэтому возврат назад (`b`) мгновенный
- **Shell**: Интерактивная командная строка с историей, fetch, search, open, clear
- **Files**: Двухпанельный файловый менеджер (стиль Volkov/Far) поверх виртуальной ФС `aios-vfs` — навигация по `AIOS://` и `HOST://`, копирование/перенос/удаление/mkdir/переименование с фоновым прогрессом, AI-превью файлов, доступ к хосту через capability-токены

| `Backspace` | Перейти в родительскую папку |

### Клавиши вкладки Web (когда активна вкладка Web)

Омнибокс принимает либо полный URL (`example.com`, `https://...`), либо обычный поисковый запрос (`как работает AIOS`) — запросы автоматически ищутся через DuckDuckGo. После `Enter` омнибокс теряет фокус, и можно сразу перемещаться по результатам (`j`/`k`) и открывать ссылку. Загрузки выполняются в фоне (TUI остаётся отзывчивым), а недавние страницы кэшируются, поэтому возврат назад (`b`) мгновенный. Окно ссылок прокручивается за выбором и показывает видимый диапазон в заголовке. **Навигационный сайдбар** слева показывает текущую страницу (отмечается `▸`) и историю посещений; сфокусируйте его клавишей `\` и переходите к любой прошлой странице.

| Клавиша | Действие |
|---------|----------|
| `g` | Фокус на омнибокс |
| `Enter` | Поиск / переход (когда омнибокс в фокусе); после `Enter` фокус снимается автоматически |
| `o` / `Enter` | Открыть выбранную ссылку (когда омнибокс не в фокусе) |
| `j` / `k` | Переместить выбор ссылки вниз/вверх |
| `b` | Назад к ранее посещённой странице |
| `B` | Открыть текущую страницу в **полноценном нативном браузере** (WebView2 — JS/CSS/картинки); окно переиспользуется между нажатиями |
| `n` | Открыть выбранную ссылку в окне нативного браузера |
| `u` / `d` | Прокрутка текста страницы вверх/вниз на 1 строку |
| `PageUp` / `PageDown` | Прокрутка текста страницы вверх/вниз на 20 строк |
| `\` | Переключить фокус навигационного сайдбара (список истории) |
| `j` / `k` | Переместить выбор сайдбара вниз/вверх (когда сайдбар в фокусе) |
| `Enter` / `o` | Открыть выбранную запись сайдбара / перезагрузить текущую страницу (когда сайдбар в фокусе) |
| `Esc` | Снять фокус с омнибокса или сайдбара |

### Команды хранилища блоков (Store)

Хранилище блоков получает блоки из трёх видов источников: GitHub (`github:owner/repo`), локальная папка (`local:path`) и HTTP-сервис обновлений (`http://host:port`). Установки попадают в `AIOS_BLOCKS_DIR` как `{name}_{version}.wasm` + sidecar JSON; при обновлениях создаётся бэкап (`.bak`) и автооткат при ошибке.

| Команда | Аргументы | Описание |
|---------|-----------|----------|
| `store list` | — | Список установленных блоков (новая версия по имени) |
| `store sources` | — | Список настроенных источников |
| `store add-source` | `<github:owner/repo\|local:path\|http://url>` | Зарегистрировать новый источник |
| `store search` | `<query> [--source NAME]` | Поиск по каталогу источника |
| `store install` | `<name> [--source NAME]` | Установить блок (последняя версия) |
| `store update` | `[name] [--source NAME]` | Проверить и применить обновления (автооткат при ошибке) |
| `store uninstall` | `<name>` | Удалить все установленные версии блока |
| `store rollback` | `<name>` | Восстановить предыдущую версию из бэкапа |
| `store publish` | `<file.wasm> [name] [version] [--key <secret_hex>]` | Опубликовать локальный wasm-файл в работающий сервис обновлений через `POST /api/v1/store/publish` (порт моста из `AIOS_BRIDGE_PORT`, по умолчанию `8080`); SHA-256 файла проверяется на сервере. С флагом `--key` (или `AIOS_STORE_SIGNING_KEY`) манифест подписывается по Ed25519 до загрузки, и мост проверяет подпись (и свою локальную политику доверия) перед установкой |
| `store trust` | `<source> [--key <public_hex>] [--clear]` | Управление доверенными ключами источника: `--key` добавляет 32-байтовый публичный ключ, `--clear` удаляет все; без флагов показывает текущие доверенные ключи. Источник с доверенными ключами принимает только манифесты, подписанные одним из них (сохраняется через конфиг `store add-source`) |
| `store sign` | `<file.wasm> [name] [version] [--key <secret_hex>]` | Подписать локальный wasm-файл по Ed25519: вычисляет SHA-256, строит манифест и пишет подписанный sidecar JSON (`{name}_{version}.json`) рядом с файлом; ключ берётся из `--key` или `AIOS_STORE_SIGNING_KEY` (32 байта, 64 hex-символа); выводит публичный ключ |
| `store verify` | `<name>` | Проверить установленный блок: пересчитать SHA-256 установленного бинарника и проверить подпись Ed25519 манифеста из sidecar; выводит `SHA-256: OK/MISMATCH` и `Signature: OK/INVALID/none` |

### Команды сетевых настроек (Net)

Читают/пишут сетевую конфигурацию через `NetSettingsBlock`, сохраняются как JSON в `AIOS_DATA_DIR`/`network.json`.

| Команда | Аргументы | Описание |
|---------|-----------|----------|
| `net get` | — | Показать текущую сетевую конфигурацию (JSON) |
| `net set` | `key=value [key2=value2 ...]` | Применить частичное обновление (например, `hostname=myhost`, `listen_port=9090`, `allow_private_access=true`, `dns={"primary":"1.1.1.1"}`); допустимые ключи: `hostname`, `listen_port`, `connect_timeout_ms`, `max_connections`, `user_agent`, `allow_private_access`, `proxy` (JSON-объект или `null`), `dns` (JSON-объект с `primary`/`secondary`/`search_domains`) |
| `net reset` | — | Восстановить заводские настройки и сохранить |

### Справка F1

Справка F1 отображает все горячие клавиши и команды shell как полноэкранную непрозрачную панель (заменяет фон дашборда, поэтому текст справки ни с чем не сливается).

| Клавиша | Действие |
|---------|----------|
| `F1` или `?` | Открыть справку |
| `F1`, `Esc` или `?` | Закрыть справку |

### AI Console (вкладка 3)

AI Console — интерактивный чат с LLM. Нажмите `i`, чтобы войти в режим запроса, введите сообщение (или `/`-команду) и нажмите `Enter`. В нижней строке отображаются текущие бэкенд/модель/температура/токены/состояние. Ответы **стримятся вживую**: растущий ответ отображается жёлтым, пока идёт запрос, а по завершении итоговый текст добавляется в ленту. Длинные ответы переносятся по ширине панели; промпты пользователя показываются цианом, ошибки — красным.

| Клавиша | Действие |
|---------|----------|
| `i` | Войти в режим запроса |
| `Enter` | Отправить запрос или выполнить слэш-команду |
| `Esc` | Выйти из режима запроса / закрыть справку |
| `Up` / `Down` | Листать последние 50 промптов |
| `h` | Открыть/закрыть встроенную панель справки |
| `q` | Выход (когда не идёт ввод) |

Слэш-команды вводятся в строке ввода (например `/status`) и выполняются по `Enter`:

| Команда | Аргументы | Описание |
|---------|-----------|----------|
| `/help` | — | Открыть панель справки + сводку команд |
| `/status` | — | Показать бэкенд, модель, состояние API-ключа, параметры, найденные локальные GGUF-модели |
| `/clear` | — | Очистить вывод чата |
| `/history` | — | Список последних промптов |
| `/system` | `<промпт>` | Задать системный промпт (без аргумента — текущий) |
| `/model` | `<имя>` | Задать модель (без аргумента — текущая) |
| `/backend` | `<groq\|openrouter\|google\|micro\|full>` | Переключить бэкенд/провайдера; локальные бэкенды сбрасывают API-ключ |
| `/key` | `<api-ключ>` | Задать API-ключ (без аргумента — очистить) |
| `/temp` | `<0.0-2.0>` | Задать температуру сэмплирования |
| `/tokens` | `<1-8192>` | Задать максимум выходных токенов |
| `/preset` | `<имя>` | Применить шаблон промпта как системный промпт |
| `/preset` | `<имя> <текст>` | Создать/перезаписать шаблон промпта |
| `/preset` | `list` / `del <имя>` | Список шаблонов / удалить шаблон |
| `/save` | — | Сохранить чат на диск (`AIOS_DATA_DIR/chat.jsonl`) |
| `/load` | — | Восстановить чат с диска, заменив текущую ленту |

Изменения бэкенда/модели/ключа асинхронно пересоздают общий `LlmEngine`, поэтому HTTP-эндпоинт `POST /api/v1/llm/query` использует ту же конфигурацию, что и консоль. Облачным бэкендам нужен API-ключ (`AIOS_LLM_API_KEY` или `/key`); локальным — GGUF-модель (`AIOS_MODEL_PATH`).

Чат **сохраняется автоматически**: после каждого завершённого ответа и при выходе он записывается в JSON Lines в `AIOS_DATA_DIR/chat.jsonl` (по умолчанию `aios_data/chat.jsonl`) и восстанавливается в ленту при следующем запуске. Встроенные шаблоны промптов: `assistant`, `code`, `translator`, `explainer` (можно настроить или добавить свои через `/preset <имя> <текст>`).

### Network & Store (вкладка 5)

| Клавиша | Действие |
|---------|----------|
| `n` | Изменить сетевые настройки (строка ввода, применяется по IPC как пары `key=value`) |
| `g` | Показать текущую сетевую конфигурацию (JSON) |
| `s` | Обновить список установленных блоков в хранилище |

Те же сетевые команды доступны из Shell как `net get` / `net set`. Операции хранилища (`store list`, `store search`, `store install`) также доступны из Shell.

### Вкладка Web (6)

Встроенный текстовый браузер загружает страницы в фоне (TUI остаётся отзывчивым). Омнибокс принимает полный URL, голый хост (`example.com`) или обычный поисковый запрос (поиск через DuckDuckGo). В боковой панели перечислены ссылки текущей страницы; текст страницы переносится по ширине панели и прокручивается. Текущую страницу можно сохранить в **закладки** (`a`) и управлять ими в **панели закладок** (`m`); закладки сохраняются в `AIOS_DATA_DIR/web_bookmarks.json`. Несколько страниц можно держать открытыми как **вкладки браузера** (`t` — новая вкладка, `x` — закрыть активную, `[`/`]` — переключение); каждая вкладка хранит свою страницу, прокрутку, выбор ссылки и историю «назад».

| Клавиша | Действие |
|---------|----------|
| `g` | Сфокусировать омнибокс |
| `Enter` | Поиск / переход (когда омнибокс сфокусирован) |
| `j` / `k` | Переместить выбор ссылки вниз / вверх |
| `o` / `Enter` | Открыть выбранную ссылку |
| `u` / `d` | Прокрутить текст страницы вверх / вниз на 1 строку |
| `PageUp` / `PageDown` | Прокрутить текст страницы вверх / вниз на 20 строк |
| `b` | Вернуться на предыдущую страницу |
| `t` | Открыть новую вкладку браузера |
| `x` | Закрыть активную вкладку браузера (последнюю закрыть нельзя) |
| `[` / `]` | Переключиться на предыдущую / следующую вкладку браузера |
| `B` | Открыть текущую страницу в полноценном нативном окне браузера (WebView2) |
| `n` | Открыть выбранную ссылку в нативном окне браузера |
| `a` | Сохранить текущую страницу в закладки (имя предзаполняется заголовком страницы) |
| `m` | Показать/скрыть панель закладок (заменяет список ссылок, пока открыта) |
| — | В панели закладок: `j`/`k` — выбор, `o`/`Enter` — открыть, `d` — удалить, `Esc` — закрыть |
| `Esc` | Убрать фокус с омнибокса или закрыть панель закладок |

### Вкладка Shell (7)

| Команда | Аргументы | Описание |
|---------|-----------|----------|
| `ps` | — | Список запущенных процессов |
| `blocks` | — | Список загруженных блоков |
| `kill` | `<pid>` | Убить процесс |
| `spawn` | `<путь-или-файл-wasm>` | Загрузить блок с диска |
| `store list` | — | Список установленных блоков |
| `store search` | `<запрос>` | Поиск в каталоге хранилища |
| `store install` | `<имя>` | Установить блок из хранилища |
| `net get` | — | Показать текущую сетевую конфигурацию (JSON) |
| `net set` | `key=value [key2=value2 ...]` | Применить частичное сетевое обновление |
| `status` | — | Uptime, состояние моста, AI Tier, RAM, число блоков |
| `logs` | — | Показать последние 20 записей журнала |
| `restart` | — | Пере-обнаружить оборудование и переинициализировать подсистемы |
| `help` / `?` | — | Показать все доступные команды |
| `clear` | — | Очистить вывод Shell |

`Esc` очищает текущую строку ввода. На вкладке Shell все нажатия клавиш идут в строку ввода, поэтому `q` выходит только с других вкладок.

### Safe Mode

С флагом `--safe-mode` AIOS загружается только с минимальным ядром: сторонние блоки с диска не обнаруживаются, HTTP/WebSocket мост выключен, в шапке показывается `SAFE MODE`. Ядро, планировщик, watchdog, LLM-движок, TUI и Shell остаются доступны.

### Горячие клавиши

| Клавиша | Действие |
|---------|----------|
| `F1`-`F8` | Переключить вкладку |
| `j` | Переместить выделение вниз |
| `k` | Переместить выделение вверх |

### Мышь

- Клик по названиям вкладок в боковой панели для переключения
- Клик по строкам в таблицах для выделения
- Клик по кнопкам для действий (Убить, Приостановить, Загрузить и т.д.)
- Ввод в полях поиска (Маркетплейс)

### Вкладки

#### System Dashboard (F1)
- **Карточки статистики**: RAM (использовано/всего), Количество блоков, Количество процессов, Статус Watchdog
- **Панель системы**: Модель CPU, ядра, потоки, AVX2/AVX-512/SSE4.2, GPU, хранилище, обнаруженный HW Tier
- **Использование RAM**: прогресс-бар + спарклайн (последние 60 сэмплов)
- **Распределение приоритетов**: столбчатая диаграмма (Background / Low / Normal / High / Critical)
- **Процессы**: таблица (PID, Имя, Приоритет, Состояние, RAM, CPU ms, Сбои) + Обновить, Убить, Приостановить, Возобновить
- **Журнал активности**: прокручиваемый журнал с цветовой кодировкой

#### WASM Blocks (F2)
- **Таблица**: ID, Имя, Версия, Состояние (бейдж), Размер, Зависимости
- **Действия**: Обновить, Загрузить блок (2-шаговый диалог), Выгрузить, Горячая замена
- **Диалог загрузки**: Шаг 1 — ввести имя блока, Шаг 2 — ввести версию, Enter/Отмена

#### AI Studio (F3)
- **Панель чата**: список сообщений, **потоковые ответы** (живая жёлтая частичная строка во время запроса), подсветка ошибок
- **Ввод**: сообщение или слэш-команда, отправка по `Enter` (или кнопка Send); фокус остаётся в поле ввода
- **Команды**: `/help /status /clear /history /system /model /backend /key /temp /tokens /preset /save /load` (та же грамматика, что и в AI Console ядра TUI)
- **Строка статуса**: бэкенд, модель, температура, токенный бюджет, состояние busy/ошибка
- **Асинхронная модель**: ответы стримятся через фоновую tokio-задачу; интерфейс остаётся отзывчивым, частичный текст появляется вживую
- **Персистентность**: чат автосохраняется в `AIOS_DATA_DIR/chat.jsonl` после каждого завершённого ответа и при закрытии окна (восстанавливается при старте); шаблоны `/preset` сохраняются в `AIOS_DATA_DIR/presets.json`

#### App Store (F4)
- **Поле поиска**: фильтр по имени, описанию или тегам
- **Таблица**: Имя, Версия, Автор, Статус (бейдж), Загрузки
- **Действия**: Установить, Обновить, Удалить
- **Статус**: показывает результат операции

#### Network Settings (F5)
- **Форма**: hostname, listen port, таймауты соединений, переключатель private access, DNS, user agent
- **Действия**: Save (применяет частичное JSON-обновление по IPC в `net_settings`), Reset (возврат к значениям по умолчанию)
- **Предпросмотр**: живой JSON редактируемой конфигурации

#### Зависимости (F6)
- **Сводка**: количество блоков + количество связей
- **Цепочка загрузки**: визуальная цепочка (блок A → блок B → блок C)
- **Таблица**: Имя блока, Зависит от, Зависят от него

#### Native Browser (F7)
- **Омнибокс**: введите полный URL (`https://...`), голый хост (`example.com`) или обычный поисковый запрос (`rust scheduler`) — Enter преобразует и загружает
- **Кнопки навигации**: Back, Forward; переключатель **Open Browser** / **Close**
- **Нативный движок**: окно браузера — настоящий WebView (WebView2 / WebKitGTK / WKWebView) с полной поддержкой куки, JavaScript и истории; первая навигация автоматически открывает окно
- **Неблокирующее открытие**: WebView запускается в фоновом потоке, поэтому дашборд остаётся отзывчивым во время старта; повторные попытки открытия в это время игнорируются, а строка состояния показывает `Opening browser: ...` / ошибку
- **Строка статуса**: показывает целевой адрес или последнее действие/ошибку

#### Files (F8)
- **Тулбар**: Обновить, Переключить панель, Сортировка, Вверх, Mkdir, Переименовать, Просмотр, Копировать, Переносить, Удалить, HOST r / HOST w (выдача capabilities `vfs:host:read` / `vfs:host:write`)
- **Две панели**: навигация по `AIOS://` (песочница) и `HOST://` (реальные пути); одиночный клик выбирает и активирует панель, двойной клик открывает папку или AI-превью файла
- **Диалог Mkdir / Переименование**: текстовое поле + OK / Отмена (Enter / Esc)
- **AI Превью**: сворачиваемая панель с умным превью выбранного файла
- **Операции**: фоновые копирование/перенос/удаление с живыми прогресс-барами и статусом завершения
- **Строка ACL**: показывает, какие capabilities хоста выданы в данный момент

- **Открытие**: `Ctrl+K` или `Cmd+K` (macOS)

- **Использование**: Введите команду на естественном языке и нажмите Enter

- **Таблица блоков**: ID, Имя, Версия, Состояние, кнопка остановки

- Поддержка WebSocket (все современные браузеры)

## Архитектурные заметки

- **TUI** использует `ratatui` + `crossterm` — работает в любом терминале, доступен через SSH
- **GUI** использует `egui` + `eframe` — нативное окно, GPU-ускоренная отрисовка
- Оба читают из одной модели `DashboardState` / `AiosApp`
- Ни один интерфейс не выполняет аппаратные операции напрямую — они запрашивают операции через планировщик/менеджер блоков
- Все данные снимковые: `DashboardState::update_from_scheduler()` (TUI) или `AiosApp::new()` (GUI, начальный)

## Daemon (`aiosd`)

### Запуск

```bash
# По умолчанию (headless, для Docker)
aiosd

# С кастомными директориями
AIOS_DATA_DIR=/mnt/data AIOS_BLOCKS_DIR=/mnt/blocks aiosd

# С профилем
AIOS_MOCK_PROFILE=legacy aiosd
```

### Переменные окружения

| Переменная | По умолчанию | Описание |
|-----------|-------------|----------|
| `AIOS_DATA_DIR` | `/app/data` | Директория persistent БД |
| `AIOS_BLOCKS_DIR` | `/app/blocks` | Директория бинарников блоков |
| `AIOS_MOCK_PROFILE` | `modern` | Профиль железа: `modern`, `legacy`, `none` |
| `RUST_LOG` | `info` | Уровень лога: `error`, `warn`, `info`, `debug`, `trace` |

Daemon выполняет ту же инициализацию, что и `aios-tui`, но без терминального интерфейса:
1. Загружает встроенные блоки (hal, ipc_bus, scheduler)
2. Загружает блоки с диска из `AIOS_BLOCKS_DIR`
3. Открывает persistent БД в `AIOS_DATA_DIR/context.redb`
4. Запускает системные процессы (ai_orchestrator, io_handler, health_monitor)
5. Запускает поток heartbeat watchdog
6. Логирует heartbeat с кол-вом процессов, RAM, состоянием watchdog каждые 10 секунд
7. Сохраняет телеметрию в БД каждые 60 секунд

## Запуск всех интерфейсов

Все четыре интерфейса (Web, TUI, GUI, Daemon) могут работать одновременно. Web SPA подключается к `aios-bridge` через HTTP/WebSocket и является чисто удалённым клиентом. TUI и GUI — встраиваемые интерфейсы, создающие собственные экземпляры `Scheduler` и `BlockRegistry` локально.
